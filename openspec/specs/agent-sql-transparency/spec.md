# agent-sql-transparency Specification

## Purpose

让智能体（AgentScope）执行过程对用户可见：用户能看到每一步在做什么、实际执行了哪条 SQL，从而把"黑箱回答"变成可核对的过程。

## Requirements
### Requirement: 智能体步骤可见

智能体流式响应 SHALL 在文本增量之外，按真实发生顺序暴露工具调用步骤，至少包含：工具名称、该步骤的开始与结束、成功或失败状态。步骤事件 MUST 与文本增量交错送达，使前端能在回答过程中即时渲染，而不是等整段回答结束后一次性给出。

#### Scenario: 查询过程中的步骤

- **WHEN** 学生向智能体提出一个数据问题，智能体调用查询工具
- **THEN** 前端依次收到"工具开始"与"工具结束"事件，并能在回答生成过程中展示对应步骤

#### Scenario: 多次工具调用

- **WHEN** 智能体先后调用表结构查看与查询工具
- **THEN** 前端收到的步骤顺序与实际调用顺序一致

### Requirement: 展示实际执行的 SQL

对每一次成功执行的查询，系统 SHALL 向前端暴露该次实际执行的 SQL 文本（即已经应用数据权限后的语句）以及其所属数据源；前端 MUST 以 SQL 代码块展示，并标明当前账号已应用数据范围。展示的 SQL MUST 与数据库实际执行的语句一致。

#### Scenario: 学生查询

- **WHEN** 学生通过智能体查询自己的成绩
- **THEN** 回答区域展示实际执行的 SQL 及其数据源标识

#### Scenario: 已应用权限

- **WHEN** 查询经过行级权限处理
- **THEN** 展示的 SQL 已包含过滤条件，且界面明确提示"已按当前数据范围过滤"

#### Scenario: 无需查询的回答

- **WHEN** 智能体未调用任何查询工具（例如仅回答概念性问题）
- **THEN** 界面不出现空的 SQL 区块

### Requirement: 失败与拒绝可见

当查询因权限、校验或执行失败而未产生结果时，系统 SHALL 向用户展示可读的失败原因，并 MUST 保持已产生的步骤与 SQL 可见。系统不得把失败包装成正常回答，也不得静默丢弃该步骤。

#### Scenario: 权限拒绝

- **WHEN** 学生请求访问其范围外的表
- **THEN** 界面显示该步骤失败及其原因，后续没有数据行或图表

#### Scenario: 执行错误

- **WHEN** SQL 执行超时或语法错误
- **THEN** 界面显示错误信息，且已展示的步骤与 SQL 不被清除

### Requirement: 展示内容不越界

暴露给前端的过程信息 MUST 只包含本次调用者有权访问的对象与数据：被裁剪的表结构、被拒绝的表名可按错误语义提示，但 MUST NOT 通过步骤、SQL 或元数据展示将其范围外的表结构或数据行带给用户。

#### Scenario: 元数据裁剪

- **WHEN** 智能体调用表结构工具
- **THEN** 前端展示的元数据只包含调用者白名单内的表与列
